# The Dira risk model — what it is, how it was tested, how accurate it is

Also surfaced in-product at **/model** (from `GET /model/card`, generated by
`uv run python scripts/train.py`). This page is the narrative companion.

## What it predicts

A per-zone **conflict-pressure probability and expected incident count for the
next 3 dekads (~30 days)** — the window shown as "Next ~30 days (start – end)"
on situation, map, and dispatch cards. It does **not** predict a calendar date
of conflict, the identity of actors, or a guaranteed occurrence.

## How it is trained

- **Label:** incidents in dekads *t+1 … t+3* (strictly future — the current
  dekad is excluded), matching the visible forecast window exactly.
- **Features:** the same bitemporal `FeatureRow` used at serve time
  (train ≡ serve): rainfall/NDVI anomalies, incident history up to the cutoff,
  neighbour pressure, exposure. Every feature is frozen at the end of dekad
  *t*; assertions in `dira_ml.train` fail the build if any feature or label
  leaks future information.
- **Split:** strict temporal train/test split with an embargo — no training
  example's label window crosses into the test period.
- **Candidates:** LightGBM vs the deterministic **TransparentIndex**;
  LightGBM only becomes the active model when its held-out Brier beats every
  baseline, otherwise TransparentIndex stays active and the reason is recorded
  on the card.

## Testing performed and results (seeded history, 264 rows / 22 zones)

Evaluation runs three temporal split fractions (0.6 / 0.7 / 0.8) plus the main
split, always comparing against three baselines:

| Model (main split) | Brier ↓ | MAE incidents ↓ |
|---|---|---|
| **LightGBM (active)** | **0.260** | **0.625** |
| TransparentIndex | 0.282 | 1.227 |
| Climatology baseline | 0.309 | 0.697 |
| CAST-style neighbourhood | 0.417 | — |
| Persistence baseline | 0.500 | — |

LightGBM shows consistent lift over every baseline across all split fractions
(Brier ≈ 0.26–0.28 in each run), which is why it is the active model.

**Where it performs best:** stable, low-volatility zones whose recent history
resembles their near future — e.g. `mandera_et_east`, `gambella_lowlands`,
`jubaland_coast` (per-zone Brier ≈ 0.08–0.09), and mid-February cycles where
signals were unambiguous.

**Where it performs worst:** zones with abrupt regime changes inside the
30-day window that the frozen features cannot see coming — e.g.
`marsabit_frontier`, `jubaland_inland`, `mandera_ke_north` (per-zone Brier
≈ 0.49–0.50). This is the model's honest failure mode: it extrapolates
pressure, it does not foresee shocks.

## Limitations (do not over-read the numbers)

- Metrics come from the **seeded/synthetic history** (only the 6 Mandera zones
  reflect the real protagonist cluster — D-011). They demonstrate honest lift
  in the demo, **not field accuracy**.
- The history is short (~12 cycles), so per-zone estimates are noisy.
- The operational band an operator sees also blends corroboration (news +
  verified field reports); the model is only the `model_risk` component.
- The model can revert to TransparentIndex on retraining if LightGBM stops
  beating the baselines — that fallback is by design (D-009).

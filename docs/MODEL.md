# The Dira risk model — what it is, how it was tested, how accurate it is

Also surfaced in-product at **/model** (from `GET /model/card`, generated by
`uv run python -m scripts.train`). This page is the narrative companion.

## What it predicts

A per-zone **conflict-pressure probability and expected incident count for the
next 3 dekads (~30 days)** — the window shown as "Next ~30 days (start – end)"
on situation, map, and dispatch cards. It does **not** predict a calendar date
of conflict, the identity of actors, or a guaranteed occurrence.

## How it is trained

- **Label:** incidents in dekads *t+1 … t+3* (strictly future — the current
  dekad is excluded), matching the visible forecast window exactly.
- **Features:** the same bitemporal `FeatureRow` used at serve time
  (train ≡ serve): rainfall/NDVI anomalies, incident history up to the cutoff,
  neighbour pressure, exposure. Every feature is frozen at the end of dekad
  *t*; assertions in `dira_ml.train` fail the build if any feature or label
  leaks future information.
- **Split:** strict temporal train/test split with an embargo — no training
  example's label window crosses into the test period.
- **Candidates:** LightGBM vs the deterministic **TransparentIndex**;
  LightGBM only becomes the active model when its held-out Brier beats every
  baseline, otherwise TransparentIndex stays active and the reason is recorded
  on the card.

## Testing performed and results

### Seeded demo panel (264 rows / 22 zones)

Historical companion metrics from the short fixture history (`DATA_MODE=seeded`,
DB `dira`):

| Model (main split) | Brier ↓ | MAE incidents ↓ |
|---|---|---|
| **LightGBM** | **0.260** | **0.625** |
| TransparentIndex | 0.282 | 1.227 |
| Climatology baseline | 0.309 | 0.697 |
| CAST-style neighbourhood | 0.417 | — |
| Persistence baseline | 0.500 | — |

### Live panel (`dira_live`, multi-year CHIRPS + MODIS NDVI + ACLED)

Trained with `DATA_MODE=live` against `DATABASE_URL_LIVE` after
`make live-bootstrap` / `make backfill-climate` / `make live-sync`:

```bash
DATA_MODE=live DATABASE_URL=$DATABASE_URL_LIVE uv run python -m scripts.train
```

**Panel size (current card):** 11 462 feature rows · 9 086 train · 2 310 test
(80/20 temporal split with embargo). Climate coverage ≈ 2012-01-01 → 2026-07-11
on the same 22 zone footprints (6 Mandera protagonists + 16 synthetic IGAD boxes).

| Model (main 80/20 split) | Brier ↓ | MAE incidents ↓ |
|---|---|---|
| **LightGBM (active)** | **0.222** | **1.473** |
| TransparentIndex | 0.260 | 2.135 |
| Climatology baseline | 0.256 | 2.155 |
| CAST-style neighbourhood | 0.290 | 1.561 |
| Persistence baseline | 0.351 | 1.743 |

LightGBM beats every baseline on held-out Brier, so it is active on `dira_live`.
Do **not** pin `transparent_v1` on the live DB — that pin is demo/`make demo`
behaviour on the seeded database only.

Re-check **/model** after training when the API points at live — the card's
`rows` / `train_rows` should be on the order of thousands.

**Where it performs best / worst** still varies by zone and cycle; see the
per-zone and per-cycle breakdown embedded in the model card JSON. Live metrics
use real CHIRPS (HTTP cache or GEE daily sums) + MODIS NDVI (GEE) + ACLED, but
still evaluate on the 22-box geometry set (D-011).

## Limitations (do not over-read the numbers)

- Seeded metrics demonstrate honest lift in the demo, **not field accuracy**.
- Live metrics use real CHIRPS/NDVI/ACLED but still evaluate on **22 boxes**
  (6 Mandera protagonists + 16 synthetic IGAD footprints — D-011).
- ACLED Research access embargos the last ~12 months of event-level data;
  recent labels may be thin.
- The operational band an operator sees also blends corroboration (news +
  verified field reports); the model is only the `model_risk` component.
- The model can revert to TransparentIndex on retraining if LightGBM stops
  beating the baselines — that fallback is by design (D-009).
- Health, FAO locust, USGS geological, and external CEWARN field ingest stay
  **honestly non-live** in Sources (`mode=unavailable` under `DATA_MODE=live`).
